框架侧可先采用的 workaround
---------------------------
更新框架与匹配的 flare-heliopause wheel 后，qualify.ppu_export、
qualify.qwen38_gguf 等导出检查可显式指定 --module-resource-abi hgpti-bare。
正式 ignition export 对应的配置为 [preparation] module_resource_abi="hgpti-bare"。
原生 recorder 按裸 ModuleResourceData 读取，并从同线程最内层 driver
materializer 的 ENTER 回调取得真实 context；卸载使用已记录 moduleId 的
唯一 context。缺少 context、跨 context 的重复 ID 均报错，不猜测地址布局。
标准 CUPTI 仍是默认；不修改 SDK、Torch、Triton 或服务回放。
这条路径仍须实机导出/独立 Rust 回放验证。本文的原始 SDK ABI 检查会继续
报告未修改库的缺陷，不能据此认定框架 workaround 失败。SDK 正式修复后，
恢复默认 cupti 模式；不能对已经修复为外层结构的 SDK 使用 hgpti-bare。

  python -m qualify.ppu_hgpti_resource_abi --sdk /path/to/PPU_SDK
请先让 LD_LIBRARY_PATH 指向同一 SDK 的 CUDA_SDK/lib64 和 lib。
脚本只依赖 Python 标准库，采用该版本导出的内部 dispatcher 与合成资源

对合成 context=0x12340000、size=64 的资源事件，两个回调实际 cbdata 为：
  domain=3, id=6: [moduleId=1, cubinSize=64, pCubin=<image address>]
  domain=3, id=7: [moduleId=1, cubinSize=64, pCubin=<same image address>]
这是裸 HGpti_ModuleResourceData，缺少 HGpti_ResourceData 外层及真实 context。
recorder 按外层结构解释后，把 pCubin 当 resourceDescriptor，再把 ELF 头
当模块描述，最终读出错误的镜像地址/长度。因此复制时崩溃。

依据与具体修复位置
------------------
NVIDIA Toolkit 的 samples/sass_source_map/sass_source_map.cu：
  HandleResource(..., const CUpti_ResourceData *pResourceData)
  DumpCudaModule(callbackId, pResourceData->resourceDescriptor)
随后 DumpCudaModule 才将 descriptor 转为 CUpti_ModuleResourceData。
其 pc_sampling_continuous 示例在模块事件中同时使用 pResourceData->context。
CUPTI Resource Callbacks 使用说明：
  https://docs.nvidia.com/cupti/main/main.html#resource-callbacks
注意 CUpti_ModuleResourceData 的简短类型说明对 cbdata 的措辞有歧义；应结合
官方示例的实际调用方式及外层 context 要求，不要仅按这一段文字实现。

SDK 2.2.1 的 HgtoolResourceCallbackHandler 在模块加载和卸载分支直接将
HgptiModuleIdMapping::GetModuleInfo() 的返回值作为 cbdata，正是裸 descriptor。
需要在两处分支构造完整 HGpti_ResourceData，并同步传入用户回调：
  HGpti_ResourceData resource{};
  resource.context = <原始 HGtool 事件的真实 context>;
  resource.resourceDescriptor = <GetModuleInfo 返回的模块描述>;
  callback(userdata, HGPTI_CB_DOMAIN_RESOURCE, cbid, &resource);
context 不能用 moduleId 代替，也不能固定为 0；保留 moduleId、完整 image
及长度。wrapper、descriptor、image 都必须在回调返回前有效。卸载完成才移除
模块记录。CUDA facade 的 cuptiSubscribe 也须交付相同 ABI。
不能在框架中猜测指针布局、跳过资源事件或关闭 context/image 完整性校验。

最小复现：不依赖 Torch、Triton、模型或 Flare 扩展
-----------------------------------------------
在 box 运行以下 Python；保留输出，不修改安装目录中的库：

python - <<'PY'
import ctypes as C
cuda = C.CDLL('libcuda.so.1')
print('cuInit:', cuda.cuInit(0))
lib = C.CDLL('/usr/local/PPU_SDK/CUDA_SDK/lib64/libcupti.so.13')
callback_type = C.CFUNCTYPE(None, C.c_void_p, C.c_int, C.c_uint32, C.c_void_p)
callback = callback_type(lambda *args: None)
subscriber = C.c_void_p()
lib.cuptiGetCallbackName.argtypes = [C.c_int, C.c_uint32, C.POINTER(C.c_char_p)]
lib.cuptiSubscribe.argtypes = [C.POINTER(C.c_void_p), callback_type, C.c_void_p]
lib.cuptiEnableCallback.argtypes = [C.c_uint32, C.c_void_p, C.c_int, C.c_uint32]
lib.cuptiUnsubscribe.argtypes = [C.c_void_p]
for cbid in (21, 742):
    name = C.c_char_p()
    print('name:', cbid, lib.cuptiGetCallbackName(1, cbid, C.byref(name)), name.value)
status = lib.cuptiSubscribe(C.byref(subscriber), callback, None)
print('subscribe:', status)
if status == 0:
    try:
        for cbid in (21, 742):
            print('enable:', cbid, lib.cuptiEnableCallback(1, subscriber, 1, cbid))
    finally:
        print('unsubscribe:', lib.cuptiUnsubscribe(subscriber))
PY

------------------
1. 在相互兼容的 HGPTI、Driver、CUDA facade 版本上，提供回调 742 的名称、
